## apps/web 규칙

- 라우팅은 App Router(`app/`). 서버 컴포넌트가 기본값 — `"use client"`는 상태·이벤트·브라우저 API가 실제로 필요한 리프 컴포넌트에만 붙인다.
- 폴더 구조는 ADR-004(FSD 채택 범위) 확정 전까지 미정. 지금은 `app/` 라우트 세그먼트 외 임의의 feature 폴더를 만들지 말고, 필요해지면 먼저 ADR로 구조를 정한다.
- WebSocket 이벤트 타입은 직접 정의하지 않고 `@maru/shared-types`에서 import한다 — 서버와 계약이 어긋나면 컴파일 타임에 잡혀야 한다.
- **상태는 소유자를 기준으로 나눈다.** 서버가 소유하면 TanStack Query, 아니면 Zustand. 판단이 애매하면 "이 값의 진실은 어디에 있는가"를 묻는다 — 새로고침 후 서버에서 다시 받아와야 하면 서버 상태다.
  - **서버 상태**(매칭·프로필 등 네트워크로 오는 데이터)는 TanStack Query. 캐시 키는 `[도메인, 식별자, ...파라미터]` 형태(예: `['session', sessionId]`)로 통일하고, 새 쿼리를 추가할 때 기존 키 네이밍과 충돌하는지 먼저 확인한다.
  - **클라이언트 상태**(통화 연결 상태, UI 토글 등 서버가 모르는 것)는 Zustand. 전이 로직은 **순수 함수 reducer로 store 밖에 두고** store는 그걸 호출하기만 한다 — 브라우저 없이 전이를 테스트할 수 있어야 한다.
  - 근거는 ADR-021. 이 ADR은 M1-04에서 작성된다.
- 방어 구역(루트 CLAUDE.md 참고)에 해당하는 파일은 초안도 작성하지 않는다 — 완성된 코드에 대한 리뷰 코멘트만 남긴다.
