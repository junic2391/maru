# store-compliance

원본: `/Users/junic/Documents/workspace/projects/maru-journal/source/Plan.md` **L117–152** (4장 신원 모델), `/Users/junic/Documents/workspace/projects/maru-journal/source/Concept.md` **L769–788** (9.7 스토어 심사 대응). Phase 4~6 작업 시작 전 반드시 원본을 다시 읽는다.

## 신원 모델 (요약)

시스템에 존재하는 "사용자"는 **계정 하나뿐**이다.

| | 랜덤 매칭 | 링크 초대 |
|---|---|---|
| 방을 만드는 쪽 | 계정 필수 | 계정 필수(호스트) |
| 참여하는 쪽 | 계정 필수 | 게스트 참가 토큰(사용자 레코드 없음) |
| 제재 대상 | 계정 | 호스트 계정(게스트 행위도 호스트가 책임) |

**신고는 모든 경로에 있어야 한다** — 링크 초대도 예외 없음. 신고가 성립하려면 신고자가 아니라 **대상이 식별 가능**하면 된다 (게스트 → 호스트 신고는 계정 없이도 작동).

## 스토어 심사 체크리스트 (Concept 9.7 FR 매핑)

| 요구 | 구현 | FR |
|---|---|---|
| EULA 동의 | 최초 계정 생성 시 1회, 동의 시각 기록 | FR-28 |
| 부적절 콘텐츠 필터링 | 브라우저 내 분류 모델 | FR-26 |
| 신고 수단 | 모든 경로의 통화 화면에 상시 노출, 종료 후에도 가능 | FR-05 |
| 악용 사용자 차단 | 계정 단위 쿨다운·차단, 재매칭 영구 배제 | FR-06 |
| 신고 대응 | 즉시 자동 연결 해제 + 재매칭 차단, 이후 백오피스 수동 검토 | FR-05·31 |
| 공개 연락처 | 약관 페이지 + 스토어 메타데이터 | FR-30 |
| 인앱 계정 삭제 | 설정 → 삭제 시작 → 확인 → 즉시 비활성화 | FR-29 |
| 동등한 프라이버시 로그인 | Apple 로그인 병행 | FR-25 |
| 연령 등급 | 스토어 메타데이터 성인 등급 | — |

`/store-check` 커스텀 명령이 이 표 기준으로 미충족 항목을 점검한다. 최종 산출물은 이 표를 그대로 옮긴 "리뷰어 노트"(테스트 계정·재현 경로 포함).
