1. `/Users/junic/Documents/workspace/projects/maru-journal/learning/INDEX.md`가 없으면 헤더(`# 학습 기록 인덱스`)와 함께 새로 만든다.

2. 이슈의 주제를 kebab-case 슬러그로 정한다(예: `pnpm-workspace-symlink-typescript`). INDEX.md를 확인해서:
   - **이미 같은 주제 파일이 있으면** `maru-journal/learning/<슬러그>.md` 맨 아래에 새 날짜 섹션을 append한다. INDEX.md는 건드리지 않는다(파일은 이미 등록돼 있으므로).
   - **새 주제면** `maru-journal/learning/<슬러그>.md`를 아래 형식으로 새로 만들고, INDEX.md에 한 줄을 추가한다:
     ```markdown
     - [<주제>](<슬러그>.md) — <한 줄 요약>
     ```

3. `maru-journal/learning/<슬러그>.md`에 다음 형식으로 섹션을 쓴다(새 파일이면 `# <주제>` 헤더 다음에, 기존 파일이면 맨 아래에 이어서):
   ```markdown
   ## YYYY-MM-DD

   **증상**: 무엇이 이상하게 동작했는가

   **진단 과정**: 무엇을 확인했고, 왜 그걸 확인할 생각을 했는가 (실제로 밟은 순서대로)

   **근본 원인**: 실제 메커니즘

   **재발 체크리스트**:
   - [ ] ...
   - [ ] ...
   ```

날짜는 오늘 날짜(currentDate 참고). 이번 대화에서 실제로 확인하고 밟은 과정만 쓴다 — 지어내거나 사후에 매끄럽게 재구성하지 않는다. 같은 주제 파일에 두 번째 날짜 섹션이 쌓이는 경우, 지난 섹션의 체크리스트만 보고 이번엔 얼마나 빨리 원인을 짚었는지가 자연스럽게 드러나게 둔다.
