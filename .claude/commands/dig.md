### 그림·표를 넣는 기준

말로 설명하면 길어지는데 관계·순서·비교가 있는 개념이면 넣는다 — 억지로 만들지 않는다. md 파일이 그대로 렌더링되는 환경(VS Code 미리보기, GitHub)을 전제로, 아래 세 형태 중 이 주제에 맞는 걸 고른다.

- **여러 주체가 순서대로 주고받는 흐름**(A가 B를 부르고, B가 C에 물어보고...) → Mermaid `sequenceDiagram`.
  ```mermaid
  sequenceDiagram
    participant Client
    participant Server
    participant Coturn
    Client->>Server: GET /turn-credentials
    Server-->>Client: {username, credential}
    Client->>Coturn: Allocate(username, credential)
    Coturn->>Coturn: 같은 비밀로 재계산해 검증
    Coturn-->>Client: 릴레이 주소 할당
  ```
- **구조·소속 관계**(누가 누구 위에 있고, 무엇이 무엇을 감싸는지) → Mermaid `flowchart` 또는 단순 박스면 ASCII art(터미널에서도 그대로 읽히는 장점).
  ```mermaid
  flowchart LR
    Browser -->|HTTPS| Caddy[":443 Caddy"]
    Caddy --> Server[":3001 NestJS"]
  ```
- **전/후 비교, A안/B안, 여러 항목의 속성 나열** → 마크다운 표.
  ```markdown
  | 항목 | Vercel | EC2 |
  |---|---|---|
  | 실행 모델 | 요청 단위, 짧게 | 계속 켜져 있음 |
  ```

세 형태 다 안 맞는(순수 개념 설명, 단일 사실 정정 등) 주제면 이 섹션 자체를 생략한다.

날짜는 오늘 날짜(currentDate 참고). 이번 대화에서 실제로 확인하고 밟은 과정만 쓴다 — 지어내거나 사후에 매끄럽게 재구성하지 않는다. 같은 주제 파일에 두 번째 날짜 섹션이 쌓이는 경우, 지난 섹션의 재발 체크리스트만 보고 이번엔 얼마나 빨리 짚었는지가 자연스럽게 드러나게 둔다.
